# 通用语义长期记忆评测基线

## 目标

本基线验证长期记忆依赖语义决策和原文证据，而不是依赖某一种编程语言、固定句式或触发词。MySQL 是事实源，ES/Milvus 是可重建召回索引；任何模型输出在写入前都必须经过服务端模式、敏感信息、稳定性、置信度和证据校验。

当前协议版本：

- 显式记忆：`memory-explicit-semantic-v2`
- 隐式抽取：`memory-semantic-v2`
- 开放事实证据核验：`memory-semantic-v2-evidence-v1`
- 结构化事实模式：`schema_version = 2`

## 离线评测集

每次调整提示词、模型、阈值或模式注册表时，至少覆盖下列类别，每类同时提供肯定、改写、否定、临时和敏感样本：

| 类别 | 应写入示例 | 不应写入示例 |
| --- | --- | --- |
| 工作上下文 | 我长期负责跨境电商供应链平台建设 | 帮我查一下供应链订单 |
| 技术偏好 | 工作中我长期以 Elixir 编程 | 这次用 Elixir 写个示例 |
| 沟通语言 | 以后和我交流都使用葡萄牙语 | 把这句话翻译成葡萄牙语 |
| 回答风格 | 回答时请一直采用苏格拉底式引导 | 这次回答简短一点 |
| 稳定偏好 | 我一直喜欢先看例子再看原理 | 今天先给我看例子 |
| 稳定事实 | 我长期在供应链领域工作 | 客户说他在供应链领域工作 |

必须加入同义改写、语序变化、大小写变化、未登记的新值和跨领域样本。不得把某个产品问题的完整句子写成生产规则。

## 判定指标

- 长期记忆精确率：不低于 98%，敏感信息误写入必须为 0。
- 稳定事实召回率：不低于 95%。
- 跨会话问题回答准确率：不低于 95%。
- 临时信息、业务记录和助手生成内容误写入率：不高于 1%。
- 模型协议失败、证据不足、策略拒绝必须分别可观测，不能统一记为 `DONE`。

生产放量应先影子运行，再按租户灰度。任一安全指标越界时关闭自动抽取开关；MySQL 中已有记忆不删除，索引可根据 Outbox 重建。

## 自动化与人工验收

自动化测试覆盖：生命周期契约、开放值规范化、原文锚定、独立证据核验、结构化持久化、精确 predicate 查询、ES/Milvus 召回、显式优先、租户隔离和删除世代。

人工端到端验收按以下顺序进行：

1. 会话 A 陈述一个未出现在任何内置别名表中的稳定事实。
2. 等待抽取任务成为 `DONE / SAVED`，确认结构化列完整且 Outbox 为 `DONE`。
3. 新建会话 B，用不同措辞询问该事实，确认能够回答。
4. 关闭 Knowledge Service，验证已知 predicate 的本人直问仍可从 MySQL 确定性回答。
5. 使用临时表达、业务查询、敏感内容和第三方事实做反例，确认不写入。
6. 删除显式记忆和清空全部记忆，分别验证可见记忆与全部世代的删除语义。

测试记录只保存样本编号、协议版本、模型版本、结果码和耗时，不在共享日志或指标标签中记录用户正文、证据或模型原始输出。
