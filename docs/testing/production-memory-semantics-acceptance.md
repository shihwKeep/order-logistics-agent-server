# 生产级跨会话记忆验收

## 前置条件

- Agent 服务、MySQL、Elasticsearch、Milvus、RabbitMQ 与重排服务均已启动且健康。
- Agent 配置中 `agent.memory.enabled=true`，当前用户的长期记忆开关已开启。
- 使用同一租户、同一登录用户完成下列步骤。

## 主流程

1. 在当前会话发送：`你以后都叫我石海文`。
2. 必须在记忆事务提交成功后才收到：`好的，已记住：用户希望被称为石海文`。不得在写入失败、超时或低置信度澄清时出现“已记住”。
3. 在同一会话发送：`你怎么称呼我？`，回答必须包含 `石海文`。
4. 新建一个会话，再发送：`你怎么称呼我？`，回答必须包含 `石海文`。
5. 完全退出桌面应用并重新启动，再发送：`你怎么称呼我？`，回答仍必须包含 `石海文`。

## 数据一致性

执行主流程第 2 步后核对：

- `agent_user_memory` 中恰有一条当前用户的有效记录：
  - `source_type = USER_EXPLICIT`
  - `visibility = VISIBLE`
  - `category = PROFILE_PREFERRED_NAME`
  - `canonical_key = profile.preferred_name`
  - `content = 用户希望被称为石海文`
  - `status = ACTIVE`
- `agent_memory_outbox` 中存在对应 `memory_id` 的 `UPSERT` 事件，并最终进入 `DONE`。
- MySQL 记忆写入或 Outbox 写入任一失败时，两张表均不得留下半成品数据。

## 删除与回归

1. 打开“我的记忆”，删除上述可见记忆并完成二次确认。
2. 等待对应删除 Outbox 事件进入 `DONE`。
3. 新建会话并发送：`你怎么称呼我？`，不得再用已删除的 `石海文` 回答。
4. 在同一会话先发送：`这次对话里叫我小石`，随后发送：`你怎么称呼我？`。即使长期记忆没有命中，也必须继续依据当前会话回答 `小石`。

## 安全回归

- `签收后多久可以退款`、`帮我查询订单 JTS0102` 等普通业务问题不得触发记忆模型或写入。
- 手机号、证件号、银行卡、健康信息、订单/退款/物流记录不得作为长期记忆保存。
- `以后这样就行` 等信息不足的表达应澄清，不得伪造记忆内容。
- 只有真实长期记忆命中才允许确定性直答；长期记忆为空或关闭时必须继续当前会话链路。
