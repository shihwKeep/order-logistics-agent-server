# 生产级会话与跨会话记忆语义设计

## 1. 背景

现有记忆基础设施已经具备 MySQL 持久化、Outbox、ES/Milvus 索引、显式记忆管理和直接记忆问答，但入口和回答编排存在两个架构缺陷：

1. 显式记忆依赖封闭句式解析。自然表达即使意图明确，也可能因为不符合固定语法而被拒绝。
2. 直接记忆问答在加载当前会话上下文之前执行。长期记忆未命中时会立即回答“没有记住”，从而忽略同一会话中刚刚出现的事实。

此外，普通聊天模型可以在没有真实写入的情况下生成“我记住了”，形成虚假确认。

本设计替代 `2026-09-11-explicit-memory-deterministic-parsing-design.md` 中“用户原文必须落入封闭语法”的约束。确定性能力继续用于安全校验和少量高置信度快速路径，不再作为自然语言准入门槛。

## 2. 目标与非目标

### 2.1 目标

- 用户以自然语言明确要求未来持续遵守或记住某个偏好时，系统能够识别并同步保存，不要求固定前缀或固定句式。
- 同一会话中的事实必须可由后续问题使用，即使该事实不属于长期记忆。
- 只有持久化事务提交成功后才能向用户确认“已记住”。
- 新会话和应用重启后，只使用已成功持久化的长期记忆。
- 继续阻止敏感个人信息、凭据、业务流水和提示词注入进入长期记忆。
- 对记忆意图、抽取、校验、写入和回答来源提供不含用户正文的可观测结果码。

### 2.2 非目标

- 不把所有聊天内容同步保存为长期记忆。
- 不把订单、退款、物流、健康诊断等业务事实转换成用户长期记忆。
- 不取消现有隐式异步抽取、Outbox、ES/Milvus 和用户管理界面。
- 不允许聊天模型绕过记忆服务直接写数据库。

## 3. 分层记忆模型

系统明确区分两层：

1. **当前会话记忆**：来自当前 conversation 的已完成历史消息，由现有 `ChatContextPreparationService` 加载。它用于保持当前对话连贯，不代表长期保存。
2. **跨会话长期记忆**：来自 `agent_user_memory` 的有效记录，以 MySQL 为事实源，ES/Milvus 用于语义候选召回。

回答时的优先级为：当前用户本轮明确表达 > 已提交的显式长期记忆 > 当前会话历史 > 隐式长期记忆。发生冲突时，更新、更明确且由用户主动给出的信息优先。

任何直接记忆问答都不得在当前会话上下文加载之前，以“长期记忆未命中”为依据直接返回否定答案。

## 4. 显式记忆混合识别

### 4.1 快速路径

保留少量无歧义形式作为低延迟快速路径，例如“请记住回答简洁”“请永久记住叫我老师”。快速路径只优化性能，不定义系统能够理解的全部表达。

### 4.2 语义路径

未命中快速路径的普通用户消息先经过宽松候选门禁。门禁只判断是否存在记忆可能性，例如包含未来约束、称呼偏好、回答偏好或明确保存意图；它不得要求完整句式匹配。

候选消息交给专用记忆模型一次性完成意图判断和结构化抽取。模型只允许输出以下三种动作：

- `SAVE`：明确要求长期保存，且可以形成一个稳定事实。
- `CLARIFY`：用户有保存意图，但内容、范围或保留期限不明确。
- `NONE`：不是显式长期记忆请求，继续正常聊天。

`SAVE` 输出固定结构：

```json
{
  "action": "SAVE",
  "category": "PROFILE_PREFERRED_NAME",
  "canonicalKey": "profile.preferred_name",
  "content": "用户希望被称为石海文",
  "evidenceText": "你以后都叫我石海文",
  "retention": "NORMAL",
  "confidence": 0.98
}
```

模型输出只是候选，不具有写入权限。

### 4.3 显式意图范围

以下表达均应识别为同一类显式记忆，而不是依赖其中某个固定词：

- 请记住，以后叫我石海文。
- 你以后都叫我石海文。
- 从今往后称呼我为石海文。
- 后面跟我交流时叫我石海文就行。
- 我希望你以后回答得简洁一些。
- 之后默认使用中文回复我。

“我平时主要做 Java 开发”属于可供隐式异步抽取的稳定事实；除非用户明确要求保存，否则不阻塞主对话链路。

## 5. 确定性安全校验

安全校验负责判断“能否保存”，不再判断“原文是否符合固定句式”。校验项包括：

- category 和 canonicalKey 必须来自允许集合并严格对应。
- evidenceText 必须能在本轮用户原文中定位，禁止模型编造证据。
- content 必须能够由 evidenceText 支持，不允许增加原文不存在的事实。
- 拒绝凭据、身份证、银行卡、手机号、精确地址、健康诊断及订单、退款、物流等业务记录。
- 拒绝提示词注入、工具调用指令、系统策略修改和删除其他数据的命令。
- 限制正文、证据和自由称呼的 Unicode 长度，拒绝控制字符及不可见字符。
- 自由称呼不再使用六项白名单。中文姓名、常用昵称和合理职称可以保存；含敏感信息、注入指令或超长内容时拒绝。
- `confidence` 低于配置阈值时不得写入，返回 `CLARIFY` 或明确的未保存提示。

## 6. 事务确认与防止虚假承诺

显式记忆链路在进入普通聊天模型之前完成：

1. 识别意图并生成候选。
2. 执行确定性安全校验。
3. 在事务内写入或更新 MySQL 记忆和 Outbox 事件。
4. 事务提交成功后返回固定确认文案“好的，已记住：……”。

任何失败都不得返回“已记住”：

- 模型超时或不可用：返回“记忆服务暂时不可用，本次内容尚未保存”。
- 安全策略拒绝：返回与原因类别对应的安全提示，不暴露内部规则。
- 内容不明确：提出一个简短澄清问题。
- 数据库事务失败：返回“本次内容尚未保存”，并记录稳定错误码。

普通聊天提示词增加约束：未经记忆写入结果确认，不得声称已经保存、永久记住或以后一定遵守。最终是否确认保存只由记忆服务生成，不能由通用模型自由生成。

## 7. 会话内与跨会话回答编排

`ChatTurnRunner` 的记忆问题处理必须位于当前会话上下文准备之后，或者在长期记忆无结果时明确返回 `NOT_HANDLED`，让请求继续使用当前会话上下文。

处理规则：

1. 存在有效显式长期记忆时，可以生成确定性回答。
2. 长期记忆没有对应事实时，不直接回答“没有记住”，而是继续进入当前会话上下文回答路径。
3. 当前会话存在明确事实时，回答该事实，但不得谎称它已经长期保存。
4. 当前会话和长期记忆都不存在时，回答尚不知道，并提示用户可以明确要求保存。
5. 记忆服务不可用与“没有记忆”必须区分；不可用时不得降级成否定事实。

这保证以下过程成立：

```text
用户：你以后都叫我石海文
系统：好的，已记住：用户希望被称为石海文
用户：你怎么称呼我
系统：我会称呼您为石海文。
```

在新会话和应用重启后，最后一句仍由已提交的长期记忆回答。

## 8. 幂等、冲突和索引

- 同一用户、租户、generation 和 canonicalKey 继续采用幂等更新，不重复创建等价有效记录。
- 用户新的显式记忆覆盖同 canonicalKey 的旧显式值。
- Outbox 在 MySQL 提交后异步同步 ES/Milvus；索引失败不回滚已经成功的 MySQL 事实，但必须重试并可观测。
- 直接类别问答优先读取 MySQL，因此刚写入后无需等待向量索引即可正确回答。
- 语义召回继续执行显式优先、候选去重和冲突抑制。

## 9. 可观测性

为显式链路记录不含正文的结果：

- `FAST_PATH_SAVED`
- `SEMANTIC_PATH_SAVED`
- `INTENT_NONE`
- `CLARIFICATION_REQUIRED`
- `REJECTED_SENSITIVE`
- `REJECTED_POLICY`
- `MODEL_TIMEOUT`
- `MODEL_PROTOCOL_ERROR`
- `PERSISTENCE_FAILED`

日志包含 requestId、conversationId、category、路径和耗时，不记录 content、evidenceText 或用户原文。指标区分意图识别、抽取、校验、事务和索引阶段。

## 10. 测试与验收

### 10.1 单元和契约测试

- 至少覆盖称呼、语言、回答风格和工作范围的同义表达、口语、标点、错别字容忍及中英文混合。
- 覆盖 `SAVE`、`CLARIFY`、`NONE` 和非法模型协议。
- 覆盖自由称呼、敏感称呼、提示词注入、业务记录和混合意图。
- 验证任何失败路径都不会生成成功确认。
- 验证长期记忆未命中时不会提前终止当前会话回答。

### 10.2 集成测试

- 使用真实 MySQL 容器验证记忆和 Outbox 同事务提交。
- 验证同 canonicalKey 更新、清空 generation、删除和重新写入。
- 验证 MySQL 已提交但 ES/Milvus 延迟时，直接类别问答仍能立即读取。

### 10.3 端到端验收

使用同一条自然语言指令依次验证：

1. **同会话**：保存后立即询问，回答一致。
2. **新会话**：创建新会话后询问，回答一致。
3. **完全重启**：退出桌面应用并重启后询问，回答一致。

每一步同时核对 MySQL 记忆状态、Outbox 状态和用户界面确认文案。任何一步失败，都不能宣称跨会话记忆完成。

## 11. 迁移策略

- 保留现有数据库结构和已保存记忆，不做破坏性迁移。
- 先引入混合意图解析器和新的结果类型，再替换 `ExplicitMemoryCommandService` 对封闭解析器的直接依赖。
- 调整直接记忆回答的未命中行为，随后增加当前会话回归测试。
- 最后更新模型约束、可观测指标和端到端验收脚本。
- 原封闭解析器可作为快速路径保留，但不得再决定语义路径是否有资格保存。
