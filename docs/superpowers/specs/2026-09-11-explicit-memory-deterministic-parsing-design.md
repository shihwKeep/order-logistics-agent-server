# 显式记忆确定性解析修复设计

## 背景

用户发送“请永久记住：叫我老师。”后，系统已经进入显式记忆处理分支，但返回“这类内容不适合作为长期记忆保存”，数据库没有新增记录。

当前链路先让模型生成 `category`、`canonicalKey`、`content` 和 `evidenceText`，再用封闭语法严格校验这些自由文本字段。即使用户内容属于已允许的安全称呼，模型对内容或证据做了合理改写，也可能因为没有完全匹配固定语法而被误拒绝。

## 目标

- 已支持的封闭类别使用确定性规则解析，不因模型措辞波动而误拒绝。
- “请永久记住：叫我老师。”能够稳定保存为永久显式记忆。
- 保持现有敏感信息拦截、租户隔离、事务边界、接口和数据库结构不变。

## 非目标

- 不扩大第一版允许保存的记忆类别或称呼集合。
- 不实现隐式自动抽取、ES/Milvus 同步消费或跨会话召回。
- 不修改前端协议和页面。
- 不放宽敏感信息与业务记录限制。

## 方案选择

采用确定性规则优先方案。

另外两种未采用方案：

1. 只把模型返回的 `evidenceText` 替换为命令正文。该方案仍会因模型生成的类别、语义键或内容改写而误拒绝。
2. 扩大正则以兼容更多模型改写。该方案需要持续追逐模型措辞，边界不稳定，也会扩大错误接受风险。

## 处理流程

1. 显式命令检测器识别命令前缀并得到去除外围标点后的命令正文，例如“叫我老师”。
2. 原有敏感内容策略继续检查完整用户原文。
3. 新增确定性候选解析器，依次使用现有封闭类别策略解析命令正文。
4. 只匹配一个类别时，生成稳定的类别、语义键、规范内容和证据：
   - 类别：`PROFILE_PREFERRED_NAME`
   - 语义键：`profile.preferred_name`
   - 规范内容：`用户希望被称为老师`
   - 证据：`叫我老师`
   - 保留类型：由“请永久记住”确定为 `PERMANENT`
5. 确定性解析成功后直接进入现有严格校验和事务写入。
6. 确定性解析失败时保持现有安全边界：本阶段不扩大可保存范围，返回现有拒绝文案，不调用模型猜测用户意图。

## 组件边界

- `ExplicitMemoryCommandDetector`：只负责识别显式命令并提取正文。
- 确定性候选解析器：只负责把命令正文映射为唯一的封闭类别候选。
- `MemoryCategoryContentPolicy`：继续作为规范化与封闭语法的唯一事实来源。
- `ExplicitMemoryCandidateValidator`：继续执行语义键、原文证据、保留类型和敏感内容校验。
- `ExplicitMemoryWriteService`：保持现有 MySQL 与 outbox 同事务写入行为。

## 安全与错误处理

- 命令原文或候选内容命中敏感信息规则时仍然拒绝。
- 同一正文匹配零个或多个类别时都拒绝，避免歧义写入。
- 不记录用户正文、模型输出或敏感值到日志和指标标签。
- 数据库异常继续映射为稳定的记忆写入失败错误。

## 测试

采用测试驱动方式：

1. 先增加失败测试，证明“请永久记住：叫我老师。”在模型输出会导致旧逻辑拒绝的情况下，期望仍产生规范候选并保存。
2. 覆盖六种允许称呼和永久/普通保留类型。
3. 验证不支持的自由昵称、敏感内容和混合意图仍被拒绝。
4. 运行记忆模块测试后，再运行完整 Maven 测试套件。

## 验收标准

- 用户发送“请永久记住：叫我老师。”时返回保存成功文案。
- `agent_user_memory` 新增一条 `USER_EXPLICIT` 永久记忆。
- `agent_memory_outbox` 在同一事务中新增对应 UPSERT 事件。
- 原有拒绝场景和全部自动化测试继续通过。
