# 统一时态用户画像记忆设计

## 背景与根因

用户消息“我今年32岁”已经进入聊天消息表，但隐式记忆任务以 `IGNORE` 完成，模型候选数、通过数和保存数均为 0。当前系统存在三个缺口：

1. 隐式抽取提示把“身份信息”笼统列为禁止项，可能误伤年龄等用户主动提供的低风险画像。
2. 长期候选只允许 `STABLE`，无法表达年龄这类可跨会话复用、但会随时间变化的事实。
3. `PROFILE` 模式只有 `preferred_name`，缺少年龄标准属性和对应的确定性问答。

Milvus 和 Elasticsearch 不是本次故障点。由于年龄没有写入 MySQL，也没有生成 Outbox 事件，所以不会进入任一索引。

## 方案比较

### 方案一：把年龄当作永久稳定字符串

实现简单，但“32岁”会自然失效，长期返回静态年龄会产生错误，不采用。

### 方案二：统一时态的结构化画像（采用）

所有结构化画像都保存观察时间和语义有效区间，并新增受控的年龄画像字段和 `TIME_BOUND` 稳定性。MySQL 保存权威事实、来源时间与历史版本；Milvus 和 Elasticsearch 继续通过 Outbox 建立派生索引。回答年龄时明确这是用户此前提供的信息，不推断生日或出生年份。

### 方案三：把所有个人陈述直接写入向量库

泛化强但缺少权威状态、删除一致性、冲突控制、数据校验和有效期管理，不符合生产要求，不采用。

## 目标行为

用户在任意会话自然表达“我今年32岁”时，系统应异步抽取隐藏画像记忆：

- `memory_type = PROFILE`
- `predicate_name = age`
- `canonical_key = profile.age`
- `value_json = "32"`
- `stability = TIME_BOUND`
- `source_type = AUTO_EXTRACT`
- `visibility = HIDDEN`
- `content = 用户曾表示年龄为32岁`

该记录写入 MySQL 后生成 `UPSERT` Outbox，沿用现有知识服务同时建立关键词和向量索引。新会话询问“我多大年纪了”“我几岁”等问题时，系统按 `age` 精确回查 MySQL 并回答：

> 根据您之前提供的信息，您当时32岁。

不根据年龄推断生日、出生年份或其他未明确提供的信息。

## 数据与生命周期

所有结构化用户画像统一记录以下时态信息，不仅年龄如此：

- `observed_at`：用户何时提供或确认这条事实。
- `valid_from`：事实从何时开始有效；当前事实未给出准确日期时取 `observed_at`，历史事实无法确定时为空。
- `valid_to`：事实何时失效；当前事实为空，已被更新的事实写入关闭时间。
- `temporal_scope`：`CURRENT` 或 `HISTORICAL`；无法判断时不保存。

`created_at` 只表示数据库记录创建时间，不能替代语义有效时间。现有结构化记忆迁移时回填 `observed_at = created_at`、`valid_from = created_at`、`temporal_scope = CURRENT`。

新增 `TIME_BOUND` 事实稳定性，用于“跨会话有用但会自然变化”的用户事实。它与 `TEMPORARY` 不同：

- `TIME_BOUND`：允许进入跨会话记忆，但必须有过期时间。
- `TEMPORARY`：仅当前会话使用，不进入长期记忆。
- `STABLE`：允许进入跨会话记忆，继续使用现有保存期限。
- `UNKNOWN`：不保存。

数据库增加迁移，将结构化记忆升级为 schema version 3，新增上述时态字段，并将稳定性约束从仅允许 `STABLE` 扩展为允许 `STABLE` 或 `TIME_BOUND`。年龄使用现有隐式记忆 TTL，不新增永不过期逻辑。

## 当前事实与历史事实

模型必须把时间表达拆成原子事实。例如“我以前是Java开发，现在是坐席”产生：

1. `occupation = Java开发`，`temporal_scope = HISTORICAL`。
2. `occupation = 坐席`，`temporal_scope = CURRENT`。

当前槽位沿用稳定键，例如 `work.occupation`，避免破坏现有记忆。历史事实使用 `work.occupation.history.<服务端哈希>`。写入新的当前职业时：

1. 关闭上一条当前职业的 `valid_to`。
2. 将上一条记录标记为 `SUPERSEDED` 并保留在 MySQL，作为可审计历史版本。
3. 通过 Outbox 删除旧的当前索引文档。
4. 写入并索引新的当前职业。

用户本轮明确提供的历史事实使用服务端生成的历史键并进入派生索引，不覆盖当前事实。问“我现在做什么”只召回 `CURRENT`；问“我以前做什么”才允许召回 `HISTORICAL`。未表达时间关系但使用现在时陈述时按 `CURRENT` 处理；确实无法判断时不保存，不能自行猜测先后顺序。

## 抽取与校验

模型继续负责语义识别，不通过整句正则决定是否保存。提示约束调整为：

- 用户主动提供的低风险个人画像可以抽取。
- 每个候选必须输出 `temporalScope`，只能是 `CURRENT` 或 `HISTORICAL`；年龄使用 `PROFILE / age / TIME_BOUND / CURRENT`。
- “以前、曾经、之前”等明确历史事实使用 `HISTORICAL`，“现在、目前、当前”使用 `CURRENT`。
- 禁止项明确为账号凭据、政府身份号码、银行卡、手机号、精确住址、健康诊断、业务记录等高风险内容，不再使用含义过宽的“身份信息”。

服务端模式负责最终裁决：

- 年龄只接受十进制整数及可选“岁”后缀。
- 合法范围为 0 至 120 岁。
- `value` 与原文 `valueEvidence` 必须规范化后相同。
- 原文证据、敏感信息、置信度和独立语义核验继续执行。
- `age` 的权威类型始终由服务端规范为 `PROFILE`，不信任模型给出的类型。
- 当前与历史查询必须按 `temporal_scope` 隔离，不能用旧画像回答当前状态。

## 画像扩展边界

本次增加年龄标准槽位，同时为安全、稳定或带时间语义的未知 `PROFILE` predicate 提供受控开放模式：

- predicate 必须为短 `snake_case`。
- canonical key 由服务端哈希生成，不直接采用模型键。
- 值必须通过字符、长度、敏感内容和证据一致性校验。
- 必须经过独立语义核验。

这使低风险画像可以逐步扩展，而不会把任意用户文本无条件保存。常用、需要确定性回答或冲突覆盖的属性仍应注册为正式槽位。

## 召回与索引

存储与召回保持现有生产链路：

1. MySQL 事务写入权威记忆。
2. 同一事务写入 Outbox。
3. Outbox Worker 调用 Knowledge Service。
4. Knowledge Service 写入 Elasticsearch 和 Milvus。
5. 普通语义召回合并关键词与向量候选。
6. 最终结果必须回查 MySQL，校验用户归属、世代、状态、版本、抑制和过期时间。

年龄类直接问题使用 `predicate_name = age` 且 `temporal_scope = CURRENT` 的 MySQL 确定性读取，避免模型忽略已经保存的画像；其他问法仍可走混合语义召回。混合召回候选同样必须回查时态字段，当前问题不得返回历史事实。

## 可见性与删除

- 自然陈述自动抽取的年龄为隐藏记忆，不在“我的记忆”列表展示。
- 用户明确要求“请记住”时，仍按显式记忆规则保存并展示。
- 清空全部记忆时，年龄与其他显式、隐式记忆一起失效并删除派生索引。
- 单条显式删除继续只影响该显式记录。

## 验证

测试必须覆盖：

1. 模型协议能够返回 `TIME_BOUND` 年龄候选。
2. `PROFILE / age` 规范化为 `profile.age`，并拒绝负数、超过120、非整数和证据改写。
3. 隐式校验接受有原文证据的年龄并要求独立语义核验。
4. 隐式提交保存 `TIME_BOUND` 并生成 Outbox。
5. 数据库迁移允许 `TIME_BOUND` 并回填所有结构化画像的观察时间和有效时间。
6. “我多大年纪了”“我几岁”等问题只召回 `age` 并安全渲染。
7. 高风险身份标识、联系方式、精确地址和健康信息仍被拒绝。
8. “以前是Java开发，现在是坐席”拆成历史与当前两条事实；当前问答不得返回Java开发。
9. 新的当前画像会关闭旧版本有效期，同时保留历史记录并更新派生索引。
10. 完整 Maven 测试集通过。

## 非目标

- 不从年龄推断生日或出生年份。
- 不把 MySQL 替换成 Milvus 或 Elasticsearch。
- 不在本次实现出生日期自动换算年龄。
- 不修改记忆管理前端布局。
