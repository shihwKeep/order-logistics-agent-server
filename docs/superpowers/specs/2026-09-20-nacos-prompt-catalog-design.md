# Nacos 提示词统一配置设计

## 1. 背景与目标

当前 Agent 主系统提示词已经由 Nacos 提供，但摘要生成、显式与隐式记忆抽取、记忆证据校验、上下文安全边界、知识库证据包装以及 Spring AI 工具/参数描述中仍存在面向模型的硬编码中文文本。

本次改造的目标是：

- 将所有生产运行时会发送给模型、或用于构造模型工具定义的提示文本统一迁移到 Nacos。
- 应用启动时一次性绑定并校验配置；运行期间不热更新，修改后重启才生效。
- 任意必需提示词缺失、为空、模板占位符错误、工具或参数配置不完整时，应用启动立即失败。
- 业务代码只保留提示词的配置引用、模板参数和渲染逻辑，不再保留中文提示词正文或兜底默认值。
- 保持已有业务行为、模型调用流程和工具执行逻辑不变。

## 2. 范围

需要外置的内容包括：

1. 主聊天系统提示词及版本。
2. 会话摘要的 System Prompt 和 User Prompt 模板。
3. 显式记忆抽取、隐式记忆抽取和记忆证据校验提示词。
4. 长期记忆和摘要注入模型上下文时使用的安全边界、低权限声明与包装模板。
5. 知识库检索证据返回给模型时使用的证据包装模板。
6. `@Tool` 工具描述以及 `@ToolParam` 参数描述，包括知识库、订单、物流、商品、客户、客户订单和售后工具。

以下内容不属于本次范围：

- 普通接口提示、日志、异常消息和前端展示文案。
- SQL、业务规则常量、枚举值和结构化协议字段名。
- Nacos 运行期热更新。
- 改变模型、温度、超时、工具路由或记忆判断算法。

## 3. 配置结构

保留现有 `agent.ai.prompt.version` 和 `agent.ai.prompt.system`，新增统一的 `agent.ai.prompt.catalog` 配置树。配置按职责拆分，而不是把所有内容放入一个无法校验的大 JSON：

- `summary`：摘要 System Prompt、User Prompt 模板。
- `memory.explicit`：显式记忆抽取提示词和输入模板。
- `memory.implicit`：隐式记忆语义抽取提示词和输入模板。
- `memory.evidence`：候选事实证据校验提示词和输入模板。
- `context.summary`：摘要上下文的标题、安全声明和包装模板。
- `context.user-memory`：用户长期记忆上下文的标题、安全声明和包装模板。
- `knowledge`：知识库证据包装模板。
- `tools`：以稳定工具名为键，配置工具描述和各参数描述。

模板使用受控的字面量占位符，例如 `{promptVersion}`、`{schemaVersion}`、`{targetOutputTokens}`、`{previousMessage}`、`{currentMessage}`、`{candidateJson}` 和 `{evidence}`。不使用 SpEL，也不允许配置执行任意表达式。

现有 Nacos 配置文件中的数据库密码、API Key 和其他敏感配置保持原样。本次只在用户提供的配置文件中增加上述提示词配置，不把敏感值复制到源码、测试或 Git 仓库。

## 4. 组件设计

### 4.1 不可变配置绑定

新增类型化的 `@ConfigurationProperties` 配置对象，按摘要、记忆、上下文、知识库和工具定义拆成嵌套结构。配置对象不提供提示词默认值，也不使用 `@RefreshScope`。

启动校验器负责：

- 校验所有必需字符串非空。
- 校验每个模板包含该场景要求的全部占位符，且不存在未知占位符。
- 校验所有已注册工具都有配置，工具的全部模型参数都有描述。
- 校验 Nacos 中没有无法映射到现有工具或参数的拼写错误项。

校验失败时抛出包含完整配置路径的启动异常，使服务在接收流量之前失败。

### 4.2 严格模板渲染

新增单一职责的严格模板渲染器。调用方传入模板和明确的参数 Map，渲染器完成字面量替换，并在缺少参数、残留占位符或出现未知参数时抛出异常。

业务类只负责准备业务数据，不再拼接提示词正文。例如隐式记忆客户端只提供上一条消息、当前消息、协议版本等参数，然后由渲染器生成最终 User Prompt。

### 4.3 工具描述动态化

工具名称继续作为稳定协议标识；工具 Java 方法、参数类型、必填关系和实际执行逻辑保持不变。源码中的 `@Tool`/`@ToolParam` 不再保存中文描述。

启动时先让 Spring AI 按现有方法签名生成基础 `ToolCallback` 和 JSON Schema，再使用 Nacos 中的工具描述和参数描述构造配置化工具定义：

- 工具级描述替换 `ToolDefinition.description`。
- 参数描述写入输入 JSON Schema 对应属性的 `description`。
- 原始回调继续负责参数反序列化和方法调用，避免重写工具执行逻辑。

配置化回调仅覆盖模型可见的定义并委托原回调执行，因此不会改变工具调用结果和异常行为。

## 5. 运行流程

1. Spring Boot 启动并从 Nacos 读取配置。
2. 配置绑定器构造不可变提示词目录。
3. 启动校验器检查非空值、模板占位符、工具和参数覆盖关系。
4. 工具配置器生成模型可见的配置化工具定义。
5. 校验全部通过后应用才完成启动。
6. 请求处理中，各业务组件从提示词目录读取固定内容，通过严格渲染器生成本次调用的 Prompt。
7. Nacos 内容发生变化时，运行中的实例不刷新；重启实例后重新绑定和校验。

## 6. 错误处理

- Nacos 未加载或关键配置缺失：启动失败。
- 必需提示词为空白：启动失败并打印配置路径。
- 模板缺少必需占位符或包含未知占位符：启动失败。
- 工具配置缺项、工具名错误、参数描述缺失或多余：启动失败。
- 运行期模板参数缺失：本轮调用快速失败并记录具体模板和参数名；正常情况下该问题应由启动校验提前发现。
- 不设置源码兜底提示词，防止配置错误被静默掩盖。

## 7. 兼容性与迁移

- 主聊天提示词沿用现有配置键，避免改变已部署配置。
- 新配置先完整加入用户提供的 Nacos 配置文件，再删除代码中的硬编码内容。
- 改造不改变公开 HTTP/SSE 接口、事件类型、数据库结构、Redis 数据结构或模型输出协议。
- 提示词版本字段继续参与现有摘要和记忆协议；只改变文本来源，不改变版本语义。

## 8. 验证策略

1. 配置绑定测试：完整配置能够成功绑定。
2. Fail-fast 测试：分别删除提示词、工具描述、参数描述或必需占位符，应用上下文必须启动失败。
3. 模板测试：输入中的换行、引号和中文能够原样进入最终 Prompt，且不执行表达式。
4. 工具定义测试：模型可见的工具描述和参数 Schema 与 Nacos 配置一致，工具调用仍委托给原业务方法。
5. 回归测试：摘要、显式记忆、隐式记忆、证据校验、知识库问答和各业务工具行为不变。
6. 静态扫描：生产 Java 源码中不再存在本次范围内的提示词正文和工具中文描述。
7. 编译与相关测试通过后，再提供完整的已补充 Nacos 配置文件供用户部署并重启验证。

## 9. 完成标准

- 本次范围内的所有模型提示词和工具描述均可在 Nacos 中找到并独立修改。
- 生产代码不含这些提示词正文，也不存在静默兜底默认值。
- Nacos 缺少任一必需项时，应用无法启动且错误能定位到具体配置键。
- Nacos 修改不会影响运行中实例，重启后新配置生效。
- 工具调用、记忆抽取、摘要生成和知识库问答的行为与迁移前保持兼容。
