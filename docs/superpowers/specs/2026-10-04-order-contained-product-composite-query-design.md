# 订单内商品复合查询修复设计

## 问题

用户询问“查询订单中的商品，并分析当前市场价格区间”时，规划器同时生成订单查询和独立商品搜索。独立商品搜索错误地把“订单 XJTS... 中的”作为商品关键词，返回空结果；复合回答上下文又只提供订单数量，没有提供订单内商品事实，最终错误回答“未查到关联商品”。

## 设计

采用订单结果作为“订单中的商品”的唯一业务事实来源：

1. 当消息包含完整订单号且商品语义表示订单归属（例如“订单中的商品”）时，规划器只生成 `order-list` 业务意图，不生成 `product-list` 意图。
2. `OrderSearchResult` 的安全回答摘要增加订单号、商品名称、SKU、规格、数量和订单成交单价等非敏感事实，让回答能够正确概括订单内商品。
3. 继续生成 `external-data-unavailable` 结果，明确系统没有外部市场数据，不能推断市场价格区间或市场定价结论。
4. 不改变普通商品名称、SKU、SPU、条码查询；这些场景仍使用 `product-list`。

## 数据流

用户问题 → 复合规划器识别完整订单号与订单归属商品语义 → 订单查询 → 订单卡片及安全商品摘要 → 外部数据边界 → 最终回答。

## 错误处理与边界

- 订单不存在或订单服务失败时，沿用既有业务查询失败处理。
- 订单存在但商品明细确实为空时，允许回答未取得订单商品明细。
- 不把收货地址、完整手机号、内部主键等敏感字段写入回答上下文。
- 不把订单成交价描述成市场价，也不推断外部市场区间。

## 测试

1. 规划器回归测试：完整订单号加“订单中的商品”只生成 `order-list`，不生成 `product-list`。
2. 工作流回归测试：订单结果中的商品名称、SKU、数量和成交价进入安全回答上下文。
3. 边界测试：普通“查询鱼油商品”仍生成 `product-list`。
4. 执行相关测试及全量 Maven 测试。
