# Agent 与桌面端知识问答接入计划

## 目标

在不改变商品、订单、物流、客户和售后工具行为的前提下，让 Agent 使用签名内部接口检索 Knowledge Service 的已发布知识，并通过 SSE 向桌面端发送不可由模型伪造的引用卡片。无可靠证据时必须固定拒答。

## 安全边界

- `tenantId`、`userId` 只取服务端认证得到的 `AgentIdentity`，不接受模型或前端参数。
- Agent 使用 HMAC-SHA256、毫秒时间戳和一次性 nonce 调用 `/api/v1/internal/knowledge/retrieve`。
- 内部密钥只从配置注入，不进入工具参数、模型提示词、SSE 或日志。
- Knowledge Service 返回的正文属于不可信证据，工具提示明确禁止把正文当作指令。
- 引用标题、位置、文档版本和 Chunk 标识只来自结构化检索响应，模型不能生成卡片字段。
- `answerable=false`、未调用知识工具或返回空证据时，回答门禁丢弃模型正文并输出固定拒答。

## 实施步骤

### 1. Agent 内部检索客户端

- 新增知识检索配置、可用性灰度和 Feign 契约。
- 新增签名器、防腐 Gateway、稳定领域响应和异常类型。
- 校验响应条数、字符串长度、分值、租户范围和 `answerable/evidences` 一致性。
- 对超时、网络和服务异常返回稳定不可用语义，不泄露下游正文。

### 2. 模型工具与硬门禁

- 新增 `search_knowledge` 只读工具并注册到本轮工具清单。
- 模型只接收有界证据文本；完整引用经 `ToolUiResult(kind=knowledge-citations)` 发布。
- 扩展当前消息查询计划，明确的规则、政策、流程、规范类问题进入必须产生知识结果的缓冲路径。
- 扩展结果门禁，验证知识结果确实可回答且至少有一条证据，否则固定拒答。

### 3. SSE 与历史契约

- 沿用现有 result SSE 和 `agent_message_result` 持久化，不新增并行协议。
- 新增知识引用载荷契约测试，保证实时结果与历史恢复使用同一结构。

### 4. Electron 引用卡片

- 扩展不可信结果解析器，只接收 `knowledge-citations` v1 的有界字段。
- 在助手回答下展示文档名、标题路径、来源位置和证据摘要。
- 首期只展示经过授权的来源元数据；可点击定位链接待 Knowledge Service 的一次性预览令牌接口完成后启用。

### 5. 验证

- Agent：签名向量、身份头、响应防腐、工具灰度、无证据拒答、原有业务工具回归。
- Desktop：引用结果校验、实时累积、历史恢复、卡片渲染和构建。
- 最终给出 Agent/Knowledge Service 两侧完整 Nacos 配置和本地联调步骤。

## 验收标准

1. 明确知识问题会调用本租户已发布知识检索。
2. `answerable=false` 或工具缺失时不会输出模型业务结论。
3. SSE 引用只能来自 Knowledge Service 结构化响应。
4. 普通用户不能伪造租户、用户、知识库范围或引用字段。
5. 已有商品、订单、物流、客户、售后自动化测试保持通过。
